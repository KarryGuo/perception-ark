## 一、Demo 简介

### 是什么

**感知方舟（PerceptionArk）** 是一款专为视障人群设计的 AI 感知眼镜系统，由硬件眼镜（钛合金镜架 + 广角摄像头 + IMU + 骨传导）和 TRAE 多智能体软件平台组成。本次初赛 Demo 以全栈 Web 应用形式呈现，手机扫码即可模拟眼镜使用，Web 端完整展示五智能体协同工作原理。

**一句话概括**：五智能体并行协作的视障感知眼镜，安全预警可抢占任何低优先级任务，0.5 秒的差别就是站着和躺着的区别。

### 面向谁

- **核心用户**：全盲及重度弱视人群（视力 < 0.05），有独立出行需求但缺乏安全辅助
- **次级用户**：视障者家属 —— 实时了解家人位置和安全状态

### 主要功能

**1. 场景感知（A01）** —— 实时描述前方路面、物体及距离，帮助视障用户"看见"周围环境

![场景感知](初赛截图/01-场景感知-Web端.png)

**2. 智能导航（A02）** —— 语音输入目的地，自动规划步行路线，支持"去最近的药店"等智能 POI 搜索

![智能导航](初赛截图/02-智能导航-路线规划.png)

**3. 安全预警（A03 · P0 优先级抢占）** —— 检测车辆、障碍物等危险，可随时打断其他 Agent 播报紧急信息；跌倒自动触发 SOS（10 秒倒计时，说"我没事"可取消）

![安全预警与SOS](初赛截图/03-安全预警-SOS倒计时.png)

**4. 文字识别（A04）** —— 读取菜单、招牌、药盒等文字信息

**5. 环境记忆（A05）** —— 学习常用路线和熟人面孔，越用越懂用户

**6. 移动端沉浸式体验** —— 手机扫码一键进入，全屏摄像头背景 + 浮动透明按钮，模拟盲人眼镜佩戴视角

![移动端体验](初赛截图/04-移动端-识别页全屏.png)
![移动端导航](初赛截图/05-移动端-导航页全屏地图.png)

## 二、Demo 创作思路

### 灵感来源

中国有超过 **1700 万** 视障人群，但全国导盲犬不足 5 万只，覆盖率不到 **0.3%**。现有辅助设备（OrCam ¥25,000+、Envision ¥15,000+）价格高昂且单模型串行架构无法实现紧急安全打断。视障者出行时，0.5 秒的延迟可能意味着一辆电动车已经撞上 —— 这不是锦上添花的工具，而是独立出行的安全底线。

### 想解决的问题

基于视障用户真实痛点：

1. **出行安全无保障** —— "过路口时不知道什么时候能走，经常被车按喇叭"
2. **信息获取困难** —— "菜单看不了，药盒说明书读不了"
3. **社交尴尬** —— "有人打招呼，不知道是谁"
4. **跌倒后孤立无援** —— "摔了一跤，趴在地上半小时才摸到手机"
5. **辅助设备太贵** —— "OrCam 要两万多，买不起"

### 为什么做这个方向

核心判断：**多智能体并行协作 + 优先级抢占机制** 是视障感知场景的技术突破口。传统单模型串行架构无法在导航播报中紧急插入安全预警，而 TRAE 的多智能体编排能力让"安全 Agent 拥有 P0 优先级、可抢占任何 Agent"成为可能。这正是 TRAE 平台能力的独特价值所在。

同时，以 ¥1,200 的 BOM 目标将可及性提升一个数量级，让科技真正服务于最需要的人群。

### 踩坑经历与解决方案

**1. Vite IPv6 绑定导致 localhost 不可访问**
- 问题：Vite 默认绑定 IPv6（[::1]:5173），Windows 优先 IPv4 解析 localhost，导致 http://localhost:5173/ 无法访问
- 解决：vite.config.js 配置 `host: '127.0.0.1'` 强制 IPv4 绑定

**2. 高德地图全屏模式下黑屏**
- 问题：CSS 选择器 `.am-bg-map > div > div` 用 `!important` 强制覆盖了高德地图内部 DOM 结构，破坏 canvas 渲染
- 解决：移除破坏性选择器，改为只覆盖 `.map-container` 的 `min-height`，初始化后延迟 200ms 调用 `map.resize()`

**3. 多源定位导致地图跳动**
- 问题：Web 端和移动端各自实例化 useGeolocation，多源定位结果（IP±10km → GPS±50m → watch 抖动）不停交替覆盖
- 解决：重写为全局单例模式，20 米移动阈值过滤 GPS 抖动，精确定位后拒绝 IP 级结果

**4. 导航目的地被篡改**
- 问题：用户说"带我去五一广场"，系统却导航到其他城市的同名地点
- 解决：移除 entity 为 null 时的"超市"fallback，优先匹配用户当前城市的 POI，清理 entity 中的"怎么走/谢谢/请问"等多余字符
